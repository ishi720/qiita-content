# はじめに

まずは、私が30秒くらいで描いたアボカドを破いて見せましょう！

![](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/3240a4a0-bbd3-4655-a373-dfe1127804d1.gif)

どうですか？破け方気持ちよくないですか？

今回は、画像をなぞった線に沿ってビリビリと破れるWebアプリを作ってみました。

VueやReact以外のフレームワークを使ってみたいので **Svelte** を使って開発しています。

それでは「紙を破く処理」について説明していきます。

# 処理の全体像

なぞってから紙が2つに分かれるまでの流れは、以下の通りです。

|順番|処理|内容|
|-|-|-|
|①|線を整える|なぞった点を等間隔に取り直し、手ブレをならす|
|②|線を延ばす|線の両端を紙の外まで延ばす|
|③|ギザギザにする|線を細かく揺らして破れ目らしくする|
|④|領域にする|線を大きな円弧で閉じて「線の右側」「線の左側」の2つの領域を作る|
|⑤|振り分ける|紙の上のサンプル点を、どちらの領域に入るかで2つのピースに分ける|
|⑥|少し離す|分かれたピースを少し離して傾ける|

![01_overview.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/e77e3149-4784-4aa2-a89a-3a323f222a5f.png)

順番に説明する前に、このアプリで一番大事な「ピースの持ち方」から説明します。

# ピースを多角形で持たない

破った紙の破片（ピース）を扱うとき、素直に考えると「ピースの輪郭を多角形として持つ」方法が思い浮かびます。

しかし、ギザギザの線で何度も破っていくと、ピースの輪郭は「多角形と多角形の交わり」を毎回計算することになります。破り線は1本で千個を超える頂点を持つこともあり、そうしたギザギザ同士の交差判定は、自前で実装するとバグの温床になりがちです。

そこで今回は、**ピースを多角形として持たず「元の紙」と「破り線のどちら側か」の組み合わせで表す**ようにしています。

```js
/**
 * 紙の破片。多角形は持たず、元の紙と破り線の制約の組で表す。
 * @typedef {object} Piece
 * @property {Paper} paper 元の紙
 * @property {Constraint[]} cons これまでの破り線。すべての制約の内側がこのピース
 * @property {number[]} idx このピースに含まれるサンプル点の番号
 * ...
 */
```

`cons`には「この破り線のこちら側」という領域が、破った回数分だけ積まれていきます。**すべての領域の内側にある部分**がそのピースです。

2回破ったピースであれば、「1本目の線の右側」かつ「2本目の線の上側」のような形になります。

![07_constraints.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/ee7e3ba4-90d8-43e5-95a3-47f7f41bad50.png)

この「かつ」を自分で計算せずに済ませるのが、`Canvas`の`clip()`です。`clip()`は呼ぶたびに今のクリップ領域との重なりに絞られていくので、制約の数だけ`clip()`を重ねるだけでピースの形がそのまま描けます。（詳しくは後述の描画で説明します）

# ① なぞった線を整える

なぞった点は、ポインターの動く速さによって間隔がバラバラです。そのままだとギザギザの細かさが場所によって変わってしまうので、まずは`resample()`で点を10px間隔に取り直しています。

続けて`smooth()`で、各点を両隣と`1:2:1`の重みで平均し、手ブレをならします。これを3回繰り返しています。

```js
let p = smooth(resample(local, 10), 3);
```

![02_resample_smooth.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/c8cb208d-34bf-4597-ada7-4612aec99fe7.png)

ここで一度なめらかにしておくのがポイントです。あとでギザギザを足すので、「手ブレのギザギザ」と「破れ目のギザギザ」が混ざらないように、先に手ブレだけを消しておきます。

# ② 線を紙の外まで延ばす

紙の端から端までぴったりなぞるのは難しいので、線の途中で指を離しても紙が破れるように、線の両端を紙の外まで延ばしています。

延ばす向きは、端から3点ぶん内側の点との差で決めています。1点だけだと最後の手ブレで向きがぶれてしまうためです。

```js
// unit() はベクトルを長さ1にする関数
const ext = Math.hypot(paper.W, paper.H) * 2; // 紙の対角線の2倍
const k = Math.min(3, p.length - 1);
const ts = unit(p[0][0] - p[k][0], p[0][1] - p[k][1]);
const te = unit(
  p[p.length - 1][0] - p[p.length - 1 - k][0],
  p[p.length - 1][1] - p[p.length - 1 - k][1]
);
p = [
  [p[0][0] + ts[0] * ext, p[0][1] + ts[1] * ext],
  ...p,
  [p[p.length - 1][0] + te[0] * ext, p[p.length - 1][1] + te[1] * ext]
];
```

延ばす長さを紙の対角線の2倍にしているので、紙のどこからどの向きに延ばしても必ず紙の外に出ます。

![03_extend.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/bce4abb8-3c2e-4d5b-ac13-523348a96937.png)

# ③ ギザギザにする

延ばした線を5px間隔に取り直し、各点を線の法線方向（線に垂直な向き）にずらしてギザギザにします。

```js
const base = resample(p, 5), n = base.length, r = Math.random;
const outer = [], inner = [], sgn = r() < 0.5 ? 1 : -1;
let walk = 0, wv = 0, mid = null;
for (let i = 0; i < n; i++) {
  // 前後の点から法線ベクトルを求める
  const a = base[Math.max(0, i - 1)], b = base[Math.min(n - 1, i + 1)];
  const [nx, ny] = unit(-(b[1] - a[1]), b[0] - a[0]);
  if (i === n >> 1) mid = [nx, ny];

  // ゆるやかなうねり（減衰するランダムウォーク）
  walk += (r() - 0.5) * 3.2; walk *= 0.9;
  wv += (r() - 0.5) * 1.6; wv *= 0.85;

  const off = walk + (r() - 0.5) * 2.6;      // ずらす量
  const w = 2 + Math.abs(wv) * 3 + r() * 1.5; // 白い芯の幅

  outer.push(base[i][0] + nx * off, base[i][1] + ny * off);
  inner.push(base[i][0] + nx * (off + sgn * w), base[i][1] + ny * (off + sgn * w));
}
```

ずらす量`off`は、2種類の揺れを足し合わせています。

|揺れ|計算|見た目|
|-|-|-|
|うねり|`walk`（前の値に乱数を足していく）|数十pxかけてゆるやかに波打つ|
|細かいギザギザ|`(r() - 0.5) * 2.6`（毎回独立した乱数）|1点ごとのささくれ|

![04_jagged.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/c27fa8b1-33a2-4386-8087-74c478500c80.png)

毎回独立した乱数だけだと、ノイズのような均一なギザギザになってしまい紙らしく見えません。前の値を引き継ぐ`walk`を足すことで、ゆるやかなうねりが生まれます。

ただし、ただ足していくだけだと線がどんどん元の位置から離れてしまうので、毎回`0.9`を掛けて0に引き戻しています。この「引き戻し付きのランダムウォーク」で、なぞった線から大きく外れずに自然に揺れる破れ目になります。

## 白い芯を出す

本物の紙を破ると、破れ目の片側にだけ紙の繊維が白く見えます。これを再現するために、輪郭を2本作っています。

|輪郭|役割|
|-|-|
|`outer`|紙のふちになる、ギザギザの輪郭|
|`inner`|画像を描く範囲。`outer`から白い芯の幅`w`だけずらしたもの|

`outer`と`inner`の間は画像を描かずに紙の色で塗るので、そこが白い芯になります。

![05_outer_inner.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/2313b92a-0191-4161-844f-003ca36c4ac3.png)

`sgn`は破るたびに`1`か`-1`をランダムで決めていて、どちら側のピースに芯が出るかが毎回変わります。芯の幅`w`にも`wv`というゆるやかに変わる値を使っているので、太いところと細いところがある、むらのある芯になります。

# ④ 線を大きな円弧で閉じて領域にする

ここまでで作ったのは、紙を横切る1本の線です。「線のこちら側」を判定したり`clip()`したりするには、閉じた図形（多角形）にする必要があります。

そこで、線の終点から始点まで、**半径10万pxの巨大な円弧**でぐるっと回って戻ることで、線の片側を囲む多角形にしています。

![06_arc_close.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/edc511c3-c996-47ae-a454-c69e697b885a.png)

円の中心は、なぞった線の真ん中です。円弧は時計回りと反時計回りの2通りあり、それぞれが線の右側・左側を囲む図形になります。

```js
const P = outer.concat(arcPos); // 線の片側を囲む領域
const N = outer.concat(arcNeg); // 反対側を囲む領域
```

半径を10万pxと極端に大きくしているのは、紙がどれだけ大きくても円弧が紙に掛からないようにするためです。紙の長辺は最大1100pxに縮小しているので、十分すぎる大きさです。

# ⑤ サンプル点でピースを振り分ける

破り線の両側の領域ができたので、あとはピースを2つに分けるだけです。

ここで、ピースを多角形で持っていないことが問題になります。「分けた片方が小さすぎないか」「ピースの中心はどこか」を知るには、ピースの形がわからないといけません。

そこで、紙を作るときに**52×52 = 2704個のサンプル点**を紙全体に格子状に置いています。

ピースは「自分に含まれるサンプル点の番号」(`idx`)を持っていて、破るときはそれぞれの点が線の片側の領域に入っているかを`inPoly()`（点と多角形の内外判定）で調べ、2つに振り分けます。

![08_sample_points.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/5a4d0b15-9206-4d58-8d14-90373b40758a.png)

```js
const A = [], B = [];
for (const i of p.idx) {
  (inPoly(p.paper.sx[i], p.paper.sy[i], cut.pos.outer) ? A : B).push(i);
}

// 片方が小さすぎるときは破らない
const min = Math.max(4, p.idx.length * 0.015);
if (A.length < min || B.length < min) { out.push(p); continue; }
```

分けた片方のサンプル点が全体の1.5%未満のときは、破らずにそのままにしています。紙の角をかすめただけで、目に見えないほど小さなピースができてしまうのを防ぐためです。

このサンプル点は、ほかにもピースの重心（回転の中心）や外接矩形の計算に使っています。正確な形ではなく「だいたいの形」がわかれば十分な処理は、すべてサンプル点で済ませています。

# ⑥ 分けたピースを少し離す

分けたばかりのピースは同じ位置に重なっているので、破れたことがわかるように少し離して傾けます。

まず、新しいピースの回転の中心を、そのピースの重心（サンプル点の平均）に移します。元のピースの中心のまま回すと、小さな破片が遠くの点を軸にぐるっと振り回されてしまうためです。

そのあと、2つのピースの重心を結ぶ向きに9pxずつ離し、0.6〜2.4度の範囲でランダムに傾けます。片方は傾きを0.7倍にして、左右対称にならないようにしています。

```js
// 2つのピースの重心（机の座標）
const ca = toWorld(a, a.px, a.py), cb = toWorld(b, b.px, b.py);
const [ux, uy] = unit(ca[0] - cb[0], ca[1] - cb[1]);
const gap = 9 / this.view.s; // 画面上で9px
const tilt = ((0.6 + Math.random() * 1.8) * Math.PI) / 180;

this.animate(a, a.tx + ux * gap, a.ty + uy * gap, a.rot + tilt);
this.animate(b, b.tx - ux * gap, b.ty - uy * gap, b.rot - tilt * 0.7);
```

離す距離は`view.s`（表示倍率）で割っているので、画像の大きさや画面のサイズに関係なく、画面上ではいつも同じくらい離れて見えます。

![09_separate.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/473097/f755907b-83ac-431a-92f2-b4276e5efe94.png)

アニメーションは380msの`ease-out`（3次）で、最初に勢いよく離れてゆっくり止まる動きにしています。OSで動きを減らす設定（`prefers-reduced-motion`）がされているときは、アニメーションせずにすぐ移動させています。

# ピースの描画

最後に、制約の組み合わせからピースを描く処理です。

```js
function bake(p) {
  // ...（サンプル点から描く範囲を決めてキャンバスを作る）
  const g = c.getContext('2d');
  const path = (a) => {
    g.beginPath(); g.moveTo(a[0], a[1]);
    for (let i = 2; i < a.length; i += 2) g.lineTo(a[i], a[i + 1]);
    g.closePath();
  };

  // 紙の範囲と、すべての outer でクリップする
  g.beginPath(); g.rect(0, 0, W, H); g.clip();
  for (const k of p.cons) { path(k.outer); g.clip(); }

  // ピース全体を紙の色で塗る
  g.fillStyle = PAPER_COLOR; g.fillRect(0, 0, W, H);

  // 芯がある制約は inner でさらにクリップしてから画像を描く
  g.save();
  for (const k of p.cons) if (k.inner !== k.outer) { path(k.inner); g.clip(); }
  g.drawImage(img, 0, 0);
  g.restore();

  // 芯の境目と、紙のふちに薄い線を引く
  g.lineWidth = 1.2; g.strokeStyle = 'rgba(110,96,70,.28)';
  for (const k of p.cons) if (k.inner !== k.outer) { path(k.inner); g.stroke(); }
  g.lineWidth = 1.4; g.strokeStyle = 'rgba(0,0,0,.14)';
  for (const k of p.cons) { path(k.outer); g.stroke(); }

  p.cache = c; p.bx = x0; p.by = y0;
}
```

冒頭で説明した通り、`clip()`を重ねるたびに描ける範囲が絞られていくので、`outer`を全部`clip()`すればピースの形になります。

そこを紙の色で塗り、さらに`inner`で絞った範囲にだけ画像を描くことで、`outer`と`inner`の間が白い芯として残ります。

`clip()`を何重にも重ねる描画は軽くないので、描いた結果はピースごとにキャンバスへキャッシュしています。毎フレームの描画では、このキャッシュを回転・移動して`drawImage()`するだけです。ピースの形は破らない限り変わらないので、キャッシュを作り直すのは新しいピースができたときだけで済みます。

# 問題点

ピースを多角形で持たない方式には、弱点もあります。

**1つのピースが、離れた2つの島に分かれることがあります。**

たとえば、U字型のピースを、左右の腕をまとめて横切るように破ったとします。このとき、線より上側の領域には左右の腕の先が両方含まれるため、離れた2つの島が「1つのピース」として扱われ、いつも一緒に動いてしまいます。

ピースは「すべての制約の内側」という条件だけで表していて、その部分がひと続きになっているかは見ていないためです。今回はこのケースには対応していません。
